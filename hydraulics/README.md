# Exploratory open-channel network

This implementation provides a replaceable extraction workflow, adjustable hydraulic scenario, and georeferenced candidate/flow layers. It does not reconstruct the archaeological water network or solve full Saint-Venant momentum equations.

`/maps/projects/caeg/people/gfx654/miniforge3/envs/qmodel/bin/python scripts/build_channel_network.py` generates JSON/GeoJSON in `assets/data/hydraulics/`. Use `--scene PATH` for a newly georeferenced LiDAR scene following the existing viewer JSON schema; cell spacing comes from coordinates. `--threshold-m2` is physical contributing area. `--stride` defaults to 1, retaining the source sampling. The builder records input SHA256 and coverage. Never resample coarse data and label it as acquired fine-resolution terrain.

Extraction routes strictly to the steepest lower D8 neighbour, accumulates terrain area, and selects edges over threshold. It does not bridge missing pixels, fill waterbodies, breach embankments, infer culverts, or route across flats. Candidate edges may be radar artefacts or general drainage slopes. Many real canals and reservoir links will be missed. A later workflow should combine archaeological linework, uncertainty-aware bare-earth terrain conditioning, surveyed structures, cross-section extraction, and manual connectivity review. Dry-ground LiDAR generally does not supply submerged bed elevations; bathymetric surveys remain necessary.

The scenario uses storage nodes with V=A_storage*h and dV/dt=external inflow + incoming Q - outgoing Q. Each link uses water-surface slope (stage_i-stage_j)/length and a rectangular flow section above the higher endpoint bed. For Manning closure Q=sign(S)*A_flow*R^(2/3)*sqrt(abs(S))/n. Adaptive explicit updates limit outgoing volume to 15% of available storage. Link transfers cancel exactly from the global water ledger. Outputs include interval mean fluxes, instantaneous flows and storage so transport can preserve water continuity. A forward Euler discretization requires time-step convergence checks for each application; positivity and global conservation alone do not establish accuracy.

Set per-network `roughness` and per-link `edge_overrides` in `scenario.json`; call `hydraulics.model.simulate(network, config)` after changes. Width, storage area, bed proxy, initial depth, external flows, Manning n, viscosity, duration and timestep are editable. The shipped 2 m width, 0.1 m depth and n=0.035 are illustrative assumptions, not archaeological estimates. No rainfall, stage boundary, weir, gate, infiltration, evaporation, lateral momentum, hydraulic jump, wave inertia or floodplain coupling is implemented. Node storage can represent a surveyed reservoir using explicit stage-storage geometry only after extending the currently constant-area representation. Missing West/East Baray bathymetry and connections must remain unresolved.

Manning roughness is not a laminar/turbulent switch. Diagnostics report Re_R=abs(u)*R/nu and Fr=abs(u)/sqrt(g*h). Conventional approximate regime labels use Re_R<500, 500–2000, >2000, configurable via `transition_re`. `laminar_wide` uses u=g*h²*S/(3*nu) and requires width/depth>=20; `auto_wide` blends laminar and Manning velocities across a configurable Reynolds interval. This pragmatic blend is an unvalidated sensitivity option; default Manning runs must be screened for low Reynolds/high Froude conditions. Hydraulically smooth turbulent flow is distinct from laminar flow. A validated friction law and cross-section treatment should replace this approximation for quantitative transition studies.

Sources: [USACE diffusion-wave equations](https://www.hec.usace.army.mil/confluence/rasdocs/ras1dtechref/6.1/theoretical-basis-for-one-dimensional-and-two-dimensional-hydrodynamic-calculations/2d-unsteady-flow-hydrodynamics/hydraulic-equations/diffusion-wave-approximation-to-the-shallow-water-equations), [USACE uniform-flow computation](https://www.hec.usace.army.mil/confluence/rasdocs/ras1dtechref/6.5/stable-channel-design-functions/uniform-flow-computations), and [USBR normal flow and friction limitations](https://www.usbr.gov/tsc/techreferences/mands/wmm/chap02_16.html). Sources support the governing approximations, not validation of this code or Angkor geometry.

Scenario `roughness` values override edge defaults; `edge_overrides` take final precedence.
